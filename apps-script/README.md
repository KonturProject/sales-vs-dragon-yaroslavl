# Бэкенд на Google Apps Script («Победи дракона», Ярославль)

Standalone-проект (не привязан к таблице через меню «Расширения»). Таблицу «победи дракона Ярославль» создаёт сам скрипт, её id хранится в свойствах скрипта — в исходнике его нет.

Игра **дневная**: каждый рабочий день новый дракон, голова — пятая часть плана этого дня. Рабочий день — пн–пт, кроме будней, отмеченных в админке выходными.

## Первый запуск

1. [script.google.com/home](https://script.google.com/home) → **Новый проект** (имя «Победи дракона Ярославль backend»), вставить `Code.gs` целиком (заменив пустую функцию).
2. В выпадающем списке функций выбрать **`setupSpreadsheet`** → **Выполнить** (Google один раз попросит доступ). Функция создаёт таблицу «победи дракона Ярославль» в Диске владельца (часовой пояс — Москва):
   - лист `Sales` — `Date | Amount | ROP | Invoice | Count` (у `ROP` выпадающий список из восьми групп `ЕСЦ1…ЕСЦ8`; `Invoice` — номер счёта импортированной оплаты; `Count` — сколько оплат означает строка, у счёта 1);
   - лист `Plans` — `Date | Plan | DayOff` (план и отметка «выходной» по дням; заполняет админка).
   Id таблицы пишется в свойства скрипта. Повторный запуск ничего не делает.
3. **Настройки проекта (⚙) → Свойства скрипта → Добавить свойство** `ADMIN_PIN` = ваш PIN (цифры). После первой смены PIN из админки (вкладка «PIN-код») открытое свойство удаляется, остаётся только солёный хеш.
4. **Начать развертывание → Новое развертывание → Веб-приложение**: выполнять от имени **меня**, доступ — **все**. Скопировать URL вида `https://script.google.com/macros/s/XXXX/exec` в `game/public/config.json` (`appsScriptUrl`, `"useMock": false`).
5. Любая правка `Code.gs` → **Управление развертываниями → ✏️ → Версия: Новая версия → Развернуть** (URL не меняется).
6. Задать план в админке, вкладка «План».

Проверка: открыть `/exec` в браузере — JSON без окна входа Google (поля `day`, `isWorkday`, `plan`, `totalToday`, `byRop`, `lastResult`, `commands`, `roster`, `leaders`, `serverNow`).

## API

Один URL. `GET` — публичный, только агрегаты: сегодняшний день (`day`, `isWorkday`, `plan` — действующий план, `planFrom` — с какого дня он взят, `totalToday`, `byRop` — оплаты групп за сегодня), итог последнего рабочего дня (`lastResult: {day, total, plan, headsCut, defeated}`), свежие команды анимаций, выбор героев и имена РГ. В выходной `plan` 0 и ничего не считается.

`POST` (тело JSON, отправляется как `text/plain` — без CORS-preflight) — все действия требуют PIN в теле:

| `action` | Параметры | Что делает |
|---|---|---|
| `login` | `pin` | проверяет PIN |
| `listPlans` | `pin, from?, to?` | будни с планом (`plan` — свой или `null`, `effectivePlan`, `planFrom`, `dayOff`); по умолчанию — эта и следующая неделя |
| `setDayPlans` | `pin, days: [{day, plan?, dayOff?}]` | план (`0…99999`, `null` — снять свой план) и отметка «выходной» по будням (до 31 дня за раз; суббота/воскресенье — ошибка). Не присланное поле не меняется |
| `listSales` | `pin, limit?` (до 200) | последние непустые строки «Sales» (новые сверху) + статус сегодняшнего дня |
| `dayCount` | `pin, rop, date` | сколько оплат у группы в рабочий день |
| `setDayCount` | `pin, rop, date, count, requestId?` | число оплат группы за рабочий день до сегодня (0–999): строки группы за этот день заменяются одной строкой с `Count` (при 0 — ни одной). Выходной — `field: 'dayoff'` |
| `importSales` | `pin, from, to, rows, dryRun?, requestId?` | импорт выгрузки (файл разбирает админка): `rows` — `[{date, amount, rop, invoice}]`, один счёт = одна оплата, до 5000 строк. **Все** оплаты с датами `from..to` заменяются присланными; остальные дни не трогаются; лист переписывается одним `setValues`. Если период включает последний рабочий день перед сегодняшним — ставится команда `dayResult` с его итогом (`announced`). `dryRun: true` ничего не пишет: `current` (что сейчас за период, в т. ч. `todayPayments`), `dayOffPayments`, `announces` |
| `changePin` | `pin, newPin` | меняет PIN (4–12 цифр), хранится хешем `salt$sha256` |
| `command` | `pin, type, args?, requestId?` | анимация на экранах: `hit {rop, count}`, `fall {hero: random\|slot_1…slot_8, mode}`, `wake`, `growl`, `confetti`, `celebrate`, `dayResult` (итог последнего рабочего дня; аргументы считает сервер). В таблицу не пишется |
| `setRoster` | `pin, roster?, leaders?` | кто стоит в слотах `slot_1…slot_8` и РГ на табличках (`{slot_1: 'Иванова А.'}`; буквы, пробел, точка, дефис, до 40 знаков). Хранится в свойствах скрипта (`ROSTER`, `LEADERS`) |
| `setGroupPins` | `pin, pins` | PIN-коды РГ `{slot_1: '123456', …}` (6–12 цифр, разные, не равны админскому); хранится только солёный хеш |
| `groupPinStatus` | `pin` | у каких групп PIN задан |

Страница РГ (`rg.html`) вместо `pin` шлёт **`groupPin`** — группа определяется по нему:

| `action` | Параметры | Что делает |
|---|---|---|
| `groupLogin` | `groupPin` | какая группа (`group: {slot, code, leader}`) и сегодня (`today: {day, isWorkday, count, total}`) |
| `groupSetCount` | `groupPin, day, count, requestId?` | число оплат своей группы **за сегодня**: `day` — день, который показывает страница; если это уже не сегодня (страница провисела с вечера) — `field: 'stale_day'` и свежий `today`; в выходной — `field: 'dayoff'` |

Ответ — `{ok: true, …}` или `{ok: false, error}`: `invalid_pin`, `locked` (+`retryAfterSec`), `bad_request` (+`field`, у списков ещё `row`), `server_error` (+`detail`). После 5 неверных PIN за 10 минут API блокируется на 10 минут (у страницы РГ свой счётчик).

## Проверка без деплоя

```bash
cd game
npm run test:backend      # 54 теста: день и план по дням, выходные и праздники, итог последнего рабочего дня, импорт, PIN, команды, герои, страница РГ
npm run mock-backend      # тот же Code.gs на http://localhost:8787/exec (PIN 1234, план 20 на сегодня, данные в памяти)
```

Dev-сборка игры и админки направляется на мок параметром `?backend=http://localhost:8787/exec`.
